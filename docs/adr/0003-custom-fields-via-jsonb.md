# Custom Fields via JSONB

Tenants need to capture custom, end-customer-specific fields on core entities (Invoices, Bills, Customers, Vendors) without per-tenant schema drift. Rather than a fully relational EAV model (a `tenant_field_values` table joined on tenant/entity/field), custom field values are stored in a `custom_fields JSONB` column on each extensible entity, paired with a `tenant_custom_field_definitions` metadata table describing each Tenant's field names/types/validation rules for UI rendering. This keeps one canonical schema and ORM model across all Tenants, at the cost of weaker DB-level type enforcement and less ergonomic SQL for reporting across custom field values — an acceptable trade-off given custom fields are a light, occasional-use capability rather than a high-volume query dimension.
