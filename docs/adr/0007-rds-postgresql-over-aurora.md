# PostgreSQL Hosting: AWS RDS over Aurora

AIARAP runs on AWS RDS PostgreSQL rather than Aurora PostgreSQL. At AIARAP's expected scale — around 10 Tenants over 2-3 years, with schema-per-tenant isolation ([ADR-0004](0004-schema-per-tenant-isolation.md)) — none of Aurora's actual differentiators (large read-replica fan-out with low replication lag, sub-30-second failover, storage autoscaling to 128TB) are load-bearing needs. Aurora carries a real cost premium over RDS (roughly 20-30% on compute, plus its own I/O-based pricing), and runs a proprietary storage engine underneath a Postgres-compatible query layer rather than the actual open-source Postgres engine RDS runs, which is a source of occasional compatibility edge cases RDS avoids entirely. If AIARAP's scale or read-throughput needs grow well beyond the current expectation, AWS provides a supported snapshot-based migration path from RDS to Aurora, so this decision carries no meaningful lock-in risk.
